2048 高保真原型 · 产品需求文档（PRD）

文档版本：v1.1（2026-11-16 修订：补充实际落地对照，见第 12 节）

目标产出：单文件可运行 HTML 高保真原型（下一步基于此 PRD 出 demo）

设计取向：还原经典 2048 手感 + 现代扁平质感 + 移动端原生级交互

1. 产品概述

1.1 产品定位

一款单玩家、零依赖、纯前端的 4×4 数字合并益智游戏。核心循环是"滑动→合并→生成新块→继续挑战"，目标先达成 2048，后可无限向 4096、8192 延展。

1.2 用户目标

• 30 秒内看懂规则，立刻能玩

• 滑动跟手、合并有反馈、分数有成长感

• 断线/刷新不丢进度，最高分长期保留

1.3 设计目标（高保真维度）

• 瓦片滑动 60fps 无闪烁

• 移动端手势跟手，不触发页面滚动

• 视觉接近原生 App：圆角、阴影、微动效、状态分层清晰

2. 用户与场景

用户类型 典型场景 核心诉求

碎片化玩家 地铁/排队掏手机玩一局 触屏顺滑、秒开即玩

桌面端玩家 办公间隙用方向键解压 键盘响应准、动画干净

策略型玩家 冲高分、记步数 撤销、最佳分、状态清晰

3. 功能需求清单

P0（必须，原型核心）

• 4×4 棋盘与数字瓦片渲染

• 上下左右滑动/按键移动

• 同值合并（每次移动每块仅合并一次）

• 分数实时计算（合并值累加）

• 最佳分持久化（localStorage）

• 新块生成：90% 出 2 / 10% 出 4

• 无效移动不生成新块、不计分

• 胜负面板：达成 2048「You Win」可继续；满盘无可合并「Game Over」

• 新游戏按钮

P1（高保真增强）

• 撤销一步（Undo）

• 滑动/合并/生成 动效（平移、弹出、淡入）

• 分数变动浮层（+N 上浮淡出）

• 进度自动存档与恢复（刷新续局）

• 移动端方向键补位（小屏可视控制区）

P2（二期可选）

• 暗色模式 / 多套配色皮肤

• 音效与震动反馈

• 步数统计、平均得分/步

• 分享截图、排行榜

4. 核心规则（逻辑基线）

1. 棋盘为 4×4 二维数组，0 表示空格
2. 每次输入一个方向，该行/列先压缩去零，再按滑动方向两两合并
3. 合并顺序：从滑动方向的边缘开始；新生成的块本次移动内不再二次合并
   • 例：[2,2,2,2] 向左 → [4,4,0,0]，不是 [8,0,0,0]

4. 若本次移动后棋盘状态无变化 → 判定为无效移动，不生成新块
5. 有效移动后，随机选一个空格生成新块：2（90%）/ 4（10%）
6. 分数增加 = 每次合并产生的新块面值之和
7. 胜利：出现 2048 块，弹「You Win」，可选「Keep Going」
8. 失败：棋盘满 且 上下左右均无相邻同值

6. 交互设计

6.1 输入方式

• 桌面：方向键 ↑↓←→；WASD 等价映射；方向键阻止页面滚动

• 移动端：棋盘区域 swipe 手势，touch-action: none

• 手势阈值：位移 < 26~28px 忽略，防误触

• 方向判定：取 dx 、 dy
 较大轴为主方向

6.2 单次移动状态流


输入方向
  → 计算目标位置（先逻辑后渲染）
  → 若无效：忽略
  → 若有效：
       1. 瓦片平移（transform 过渡 ~100-150ms）
       2. 合并块弹跳（scale 1.15 脉冲）
       3. 新块淡入（scale 0→1）
       4. 分数更新 + 浮层
       5. 生成新块
       6. 判定胜负


6.3 状态定义

状态 表现

Idle 等待输入，动画锁释放

Animating 输入锁定 ~200ms，防连击错乱

Won 覆盖层显示，可继续

Over 覆盖层显示，仅可重开

Recovered 刷新恢复历史棋盘，跳过入场动画

7.2 瓦片色阶（按数值）

• 2：#eee4da

• 4：#ede0c8

• 8：#f2b179

• 16：#f59563

• 32：#f67c5f

• 64：#f65e3b

• 128：#edcf72（文字浅色）

• 256：#edcc61

• 512：#edc850

• 1024：#edc53f

• 2048：#edc22e

• ≥4096：深橙红渐变，保持对比度

7.3 字体与排版

• 字体：系统无衬线（-apple-system / Segoe UI / PingFang SC）

• 瓦片字号分档：2~64 大字号，128~512 略缩，1024+ 再缩一档，防止溢出

• 圆角：棋盘 6px，瓦片 3px

• 阴影：瓦片轻投影，合并时短暂加深

7.4 动效参数

• 滑动过渡：transform 120ms ease

• 新块出现：scale(0→1) 200ms

• 合并脉冲：scale(1→1.15→1) 200ms

• 分数浮层：上移 20px + 淡出 600ms

8. 数据模型

gameState = {
  grid: number[4][4],        // 0 为空
  score: number,
  best: number,              // localStorage
  status: 'idle' | 'won' | 'over',
  keepGoing: boolean,
  history: snapshot          // 仅存一步用于撤销
}


• 每次有效移动前深拷贝 grid 入 history

• 刷新加载：读 localStorage → 有则恢复，无则初始化两颗起始块

9. 异常与边界

• 动画过程中忽略新输入（加锁）

• 触摸区域仅限棋盘，避免误触按钮

• 4096+ 数值：预设色阶兜底，不出现无样式块

• 本地存储被禁用：降级为内存态，不阻塞游戏

• 撤销在"无历史/刚恢复"时置灰

11. 技术约束（给开发看的）

• 单文件 index.html，内联 CSS/JS，零依赖零构建

• 瓦片用 position:absolute + transform:translate()，不走重排

• 逻辑层与渲染层分离：先算状态，再驱动画

• 移动端 touch-action:none + overflow:hidden

12. 落地对照（v1.1 补充）

本节记录「文档写的」与「最终做出来的」之间的差异，避免后续维护按旧文档改错地方。

项目 | 本文档原方案 | 实际落地
视觉 | 经典 2048 原版配色（#faf8ef / #bbada0） | 改为 Q 版可爱卡通：奶油底 + 马卡龙色块 + 深棕描边（3px）+ 硬投影，配色与「猜拳对决」项目统一
文件组织 | 单文件 index.html，CSS/JS 内联 | 拆为 index.html + assets/css/style.css + assets/js/game.js + assets/js/app.js（项目规范要求，不内联）
多端 | 仅 web | 一份 HTML 作唯一视觉基准，外套 Windows（WebView2）与安卓（WebView）两层壳，三端共用同一份页面
数据模型 | grid 存数字 0/2/4… | 改为存方块对象 `{id, v}`，靠 id 让界面层认出「同一块」，才能做连续滑动动画
move 返回值 | 未定义 | `{moved, gained, pairs:[{dead,into}], spawned, won}`，pairs 提供被吃块的消失目标格
刷新恢复进度 | P1 要求「刷新续局」 | 未实现。只持久化最高分（`localStorage` 的 `g2048.best`），刷新即开新局
新块概率 | 90% 出 2 / 10% 出 4 | 与文档一致
撤销 | 一步 | 与文档一致，快照含 grid/score/won/over
新游戏确认 | 覆盖层「确认重开」 | 与文档一致，为页面内模态框（不用原生 confirm）
动画参数 | transform 120ms / 新块 200ms / 脉冲 200ms | 位置迁移 130ms，脉冲与淡入走 CSS keyframes，实际时长略窄
兼容 | 未要求 | 补老内核兜底：`aspect-ratio`、`inset` 在 Chromium 88 以下会崩，改用 padding 与四边定位
